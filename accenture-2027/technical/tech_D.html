Type casting
Implicit (widening): int → long → float → double, done automatically.
Explicit (narrowing): (int) 9.7 = 9, which truncates.
Integer overflow
Going past the maximum wraps around: in Java, Integer.MAX_VALUE + 1 becomes the most negative int.
Integer vs real division
7 / 2 = 3 but 7.0 / 2 = 3.5. -7 / 2 = -3 in C/Java (truncates toward 0).
if / else-if / switch
In a switch, a missing break falls through to the next case.
for / while / do-while
do-while always runs at least once, because the condition is checked at the end.
Short-circuit
In a && b, b isn't evaluated if a is false. In a || b, b isn't evaluated if a is true.
Functions: call by value vs reference
By value: a copy is passed, so the original is unchanged. By reference: the function works on the original. Java passes everything by value (for objects, the value is the reference).
Arrays & strings
An array is a fixed-size, contiguous block, 0-indexed, with O(1) access by index. Java Strings are immutable. Use StringBuilder for repeated changes. A C string ends with '\0'.
D2
Organise data

Data Structures

Stack: LIFO
push, pop, peek, all O(1). Overflow when full, underflow when empty.
Uses: function calls (the call stack), undo, browser back button, balanced brackets, expression evaluation, DFS.
Queue: FIFO
enqueue at the rear, dequeue from the front, O(1).
Variants: circular queue, deque (both ends), priority queue (by priority, often a heap).
Uses: CPU scheduling, printers, BFS.
Linked list
Nodes of data + next pointer. Insert or delete at the head is O(1). Access by index is O(n). Types: singly, doubly (prev + next) and circular.
Trees & graphs
Binary Search Tree: left < node < right, with search O(log n) on average and O(n) when skewed. Traversals: in-order (sorted output), pre-order, post-order. A graph has vertices and edges. BFS uses a queue; DFS uses a stack or recursion.

Evaluating postfix: scan left to right. Push numbers. When you meet an operator, pop the top two, apply the operator as (second-popped op first-popped), and push the result. Example: 5 1 2 + 4 * + 3 - → 1 + 2 = 3, 3 × 4 = 12, 5 + 12 = 17, 17 − 3 = 14.

Searching, Sorting & Big-O

Linear search
Checks each element: O(n). Works on unsorted data.
Binary search
Needs sorted data. Compare with the middle and discard half each step: O(log n). Searching 1,024 items takes at most 10–11 comparisons.

Big-O from code

PatternComplexity
Fixed number of stepsO(1)
Halving or doubling loop (i = i*2, binary search)O(log n)
Single loop to nO(n)
Loop to n containing a halving loop; merge sortO(n log n)
Two nested loops to nO(n²)
Naive recursive Fibonacci; all subsetsO(2ⁿ)

Rules: drop constants (O(2n) = O(n)), keep only the dominant term (O(n² + n) = O(n²)). Sequential blocks add, and nested blocks multiply. Growth order: 1 < log n < n < n log n < n² < 2ⁿ < n!

DBMS Basics

DBMS vs RDBMS
An RDBMS stores data in related tables (rows = records/tuples, columns = attributes) and uses SQL. Examples: MySQL, Oracle, PostgreSQL, SQL Server. NoSQL examples: MongoDB, Cassandra.
ACID (transactions)
Atomicity: all or nothing. Consistency: valid state to valid state. Isolation: concurrent transactions don't interfere. Durability: committed data survives crashes.
KeyDefinition
Super keyAny set of columns that uniquely identifies a row
Candidate keyA minimal super key (no extra columns)
Primary keyThe chosen candidate key: unique + NOT NULL, one per table
Alternate keyCandidate keys not chosen as primary
Foreign keyA column referencing another table's primary key (referential integrity)
Composite keyA key made of 2 or more columns
Unique keyValues must be unique but can be NULL (one NULL in most databases)
Normal formRule
1NFAtomic (single) values, no repeating groups
2NF1NF + no partial dependency on part of a composite key
3NF2NF + no transitive dependency (non-key → non-key)
BCNFEvery determinant is a candidate key

DELETE
DML. Removes rows (can use WHERE). Can be rolled back. Slower.
TRUNCATE
DDL. Removes all rows quickly but keeps the table structure.
DROP
DDL. Removes the whole table: structure and data.
Query order and joins. Written order: SELECT … FROM … WHERE … GROUP BY … HAVING … ORDER BY. WHERE filters rows before grouping, and HAVING filters groups. INNER JOIN returns only matching rows. LEFT JOIN returns all left rows (NULL where there's no match), and RIGHT JOIN returns all right rows. An ER diagram shows entities (rectangles), attributes (ovals) and relationships (diamonds) with cardinality 1:1, 1:N or M:N.
