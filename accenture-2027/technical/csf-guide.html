Programming Fundamentals

How code becomes a running program, how data is stored, and how functions, memory, arrays and strings work. These are the basics behind every other topic.

F1
From source to execution

How Programs Run

Source code (.c)→ preprocessor →Compiler→Object code (.o)→ linker →Executable→ loader →Running in memory
ToolWhat it does
CompilerTranslates the whole program into machine code before running it. Errors are reported together, and the program runs fast (C, C++, Go)
InterpreterTranslates and runs line by line. It stops at the first error and runs more slowly (Python, JavaScript, Ruby)
Hybrid (Java, C#)Compiled to bytecode, which runs on a virtual machine (the JVM/CLR). A JIT compiler turns hot code into native code. "Write once, run anywhere"
AssemblerAssembly language → machine code
Linker / LoaderThe linker combines object files and libraries into an executable. The loader places the executable in memory to run
Language levels
Machine language (binary) → assembly (mnemonics like MOV, ADD) → high-level (C, Java, Python). C is often called "middle level".
Paradigms
Procedural (C) · Object-oriented (Java, C++) · Functional (Haskell, plus lambdas in many languages) · Scripting (Python, JS).
Error types
Syntax (compile time: a missing ;) · Runtime (divide by zero, null pointer) · Logical (runs, but gives the wrong answer).

Integer ranges

Implicit (widening) conversion: done automatically when no data is lost. byte → short → int → long → float → double. In mixed expressions, the smaller type is promoted: 5 / 2.0 = 2.5, but 5 / 2 = 2.
Explicit (narrowing) casting: you have to ask for it, and data may be lost. (int) 7.9 = 7 (truncates toward 0) · (int) -7.9 = −7 · (char) 66 = 'B' · (byte) 130 = −126.
Floating point: stored in binary (IEEE 754), so many decimals are approximations. 0.1 + 0.2 == 0.3 is false. float has about 7 significant digits and double about 15–16. Never compare floats with ==; check whether they're close enough instead.

Recursion vs iteration: recursion is cleaner for trees and divide-and-conquer, but uses stack memory. Iteration is usually faster and uses O(1) space.

F4
Functions & memory

Functions, Memory & Pointers

Parameters vs arguments
Parameters are the variables in the function definition. Arguments are the values passed in the call. A declaration (prototype) gives the signature, and a definition provides the body.
Call by value vs reference
By value: a copy is passed, so the caller is unchanged (C's default, and Java's primitives). By reference / pointer: the function works on the original (C pointers, C++ &). Java passes object references by value, so it can change an object's fields but can't reassign the caller's variable.

Memory layout of a running C program

Stacklocals, parameters, return addresses · grows ↓
↓ free ↑
Heapmalloc / new · grows ↑
Data / BSSglobals and statics
Text / Codemachine instructions

Each function call pushes a stack frame. Recursion that's too deep causes a stack overflow.

Java has no explicit pointers. It uses references, and the garbage collector frees unreachable objects automatically. Inline functions (C/C++) ask the compiler to paste the body in place of the call. Function overloading means the same name with different parameters (C++ and Java, but not C).

Array: a fixed-size, contiguous block of same-type elements, 0-indexed, with O(1) random access.
1D address = base + i × size.
2D row-major (C, Java): base + (i × columns + j) × size.
Column-major (Fortran, MATLAB): base + (j × rows + i) × size.

Java: String is immutable, so methods return new strings. Use StringBuilder (fast, mutable) or StringBuffer (thread-safe) for repeated changes.

Organising data

Linear Data Structures

Classification: linear (elements in a sequence: array, linked list, stack, queue) vs non-linear (hierarchical or networked: tree, graph) · static (fixed size: array) vs dynamic (grows: linked list) · a primitive type (int, char) vs an abstract data type (ADT: stack, queue, defined by its operations).
ArraySingly linked list
MemoryContiguous, fixed sizeScattered nodes (data + next pointer), dynamic
Access the i-th elementO(1)O(n): you must traverse
Insert or delete at the frontO(n): shift everythingO(1)
Insert at the endO(1) if there's spaceO(n), or O(1) with a tail pointer
Extra memoryNoneA pointer per node
Cache friendlinessHighLow

Linked-list types: singly (next) · doubly (prev + next, so it can go backwards, and deleting a known node is O(1)) · circular (the last node points to the head). To reverse a singly list, use three pointers: prev, curr and next.

Stack: LIFO (Last In, First Out) Operations: push, pop, peek/top, isEmpty, all O(1). Overflow = pushing onto a full stack. Underflow = popping an empty one.
Uses: the function call stack and recursion, undo/redo, the browser back button, balanced brackets, expression conversion and evaluation, DFS, backtracking.
push 10push 20pop → 20push 30push 40pop → 40pop → 30
Queue: FIFO (First In, First Out) enqueue at the rear, dequeue from the front, both O(1).
Circular queue: rear = (rear + 1) mod n, which reuses the space freed at the front. Deque: insert and delete at both ends. Priority queue: highest priority out first (usually a heap).
Uses: CPU and printer scheduling, BFS, buffers, call centres.
Infix → postfix (shunting-yard)
  1. Operand → write it to the output.
  2. ( → push it. ) → pop to the output until you reach (.
  3. Operator → pop operators of higher or equal precedence to the output, then push it.
  4. At the end, pop everything left.
A + B * C - D → A B C * + D - · (A + B) * C → A B + C *
Evaluating postfix with a stack Scan left to right. Push numbers. When you meet an operator, pop the top two (second-popped OP first-popped) and push the result.
5 1 2 + 4 * + 3 -: 1 + 2 = 3 → 3 × 4 = 12 → 5 + 12 = 17 → 17 − 3 = 14.
Prefix (Polish notation) works the same way, scanning right to left.

Trees, Heaps, Graphs & Hashing

TraversalOrderResult for this BST

Tree terms: root · parent/child · siblings · leaf (no children) · internal node · depth (edges from the root) · height (longest path down to a leaf) · degree (number of children) · subtree.
Binary tree facts (root at level 0)
Max nodes at level i = 2ⁱ · max nodes at height h = 2ʰ⁺¹ − 1 · min height for n nodes ≈ ⌊log₂n⌋ · a tree with n nodes has n − 1 edges · leaves = nodes with 2 children + 1 (in a full binary tree).
Types: full (0 or 2 children each) · complete (every level full except possibly the last, filled left to right: heaps) · perfect · skewed (a chain).
BST
left < node < right. Search, insert and delete are O(log n) on average but O(n) if skewed (sorted input). AVL and Red-Black trees self-balance to guarantee O(log n).
Heap (complete binary tree in an array)
Min-heap: parent ≤ children (min at the root). Max-heap: parent ≥ children. For index i, the children are 2i + 1, 2i + 2 and the parent is (i − 1)/2. Insert and delete are O(log n), peek is O(1), and building a heap is O(n).
Graphs
Vertices + edges · directed or undirected · weighted · cyclic or acyclic (a DAG). Stored as an adjacency matrix (V² space, O(1) edge check) or an adjacency list (V + E space, better for sparse graphs). BFS uses a queue (shortest path in unweighted graphs). DFS uses a stack or recursion.
Hashing: a hash function maps a key to an index, giving O(1) average search, insert and delete. A collision happens when two keys map to the same index. Load factor α = n / table size, and you rehash when it gets high.
Collision resolution: chaining (a linked list at each index) · open addressing: linear probing (i + 1, i + 2…, which causes clustering), quadratic probing (i + 1², i + 2²…), double hashing.

Also good to recognise: a trie (prefix tree, for autocomplete) · B / B+ trees (database indexes) · graph algorithms: Dijkstra (shortest path), Prim and Kruskal (minimum spanning tree), topological sort (DAGs).

Find and order

Searching & Sorting

Linear search: check each element. O(n), and works on any array. Best case O(1) (the first element).
Binary search: needs sorted data with random access. Compare with the mid = (lo + hi) / 2 element and discard half each step. O(log n), so at most ⌊log₂n⌋ + 1 comparisons (1,000 elements → 10). It doesn't work efficiently on linked lists.

Which sort when? Nearly sorted or small data → insertion · guaranteed n log n or linked lists → merge · fastest in practice for in-memory arrays → quick · O(1) space with guaranteed n log n → heap · fewest swaps → selection (n − 1 swaps) · small-range integers → counting.
F9
How fast, how big

Time & Space Complexity

Big-O (O)
An upper bound, used for the worst case. "Grows no faster than…"
Big-Omega (Ω)
A lower bound, linked to the best case. "Grows at least as fast as…"
Big-Theta (Θ)
A tight bound: both O and Ω. "Grows exactly like…"

Rules: drop constants (O(3n) = O(n)) · keep the dominant term (O(n² + n log n) = O(n²)) · sequential steps add and nested steps multiply · different inputs keep separate variables (O(a + b) or O(a·b)). Growth order: O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!).

Space complexity is the extra memory used: iterative sum O(1) · copying an array O(n) · recursion depth d uses O(d) stack space (recursive factorial O(n), binary search recursion O(log n)) · merge sort O(n).

DBMS Concepts & Keys

Why a DBMS instead of files?
It reduces redundancy and inconsistency, and provides concurrent access, security, integrity constraints, backup and recovery, and a query language (SQL). An RDBMS stores data in related tables: MySQL, Oracle, PostgreSQL, SQL Server. NoSQL databases (MongoDB, Cassandra, Redis) use documents, columns or key-value pairs.

Constraints: NOT NULL · UNIQUE · PRIMARY KEY · FOREIGN KEY (ON DELETE CASCADE / SET NULL) · CHECK (salary > 0) · DEFAULT. Integrity types: entity (the primary key isn't null), referential (a foreign key matches an existing primary key), domain (valid values).

DB2
Design

ER Model & Normalisation

ER diagram symbols
Entity = rectangle (a weak entity has a double rectangle) · attribute = oval (key = underlined, multi-valued = double oval, derived = dashed) · relationship = diamond · cardinality 1:1, 1:N, M:N · participation total (double line) or partial. An M:N relationship becomes a separate table.
Why normalise? To remove redundancy and the anomalies it causes: insertion (you can't add data without unrelated data) · update (the same fact stored in many rows gets out of sync) · deletion (deleting one fact loses another).
FormRuleFix
1NFAtomic values: no lists or repeating groups in a cell"Java, SQL" in one cell → one row per skill
2NF1NF + no partial dependency (a non-key column depending on part of a composite key)(student, course) → student_name? Move student_name to a Student table
3NF2NF + no transitive dependency (non-key → non-key)emp → dept_id → dept_name? Move dept_name to a Department table
BCNFFor every dependency X → Y, X is a super key (a stricter 3NF)Decompose further

Higher forms (4NF for multi-valued dependencies, 5NF for join dependencies) are rarely asked. Denormalisation deliberately adds redundancy for read speed, for example in data warehouses.

The query language

SQL: Commands, Clauses & Joins

FamilyCommandsNote
DDL (Definition)CREATE, ALTER, DROP, TRUNCATE, RENAMEChanges the structure. Auto-commits
DML (Manipulation)INSERT, UPDATE, DELETE (MERGE)Changes the data. Can be rolled back
DQL (Query)SELECTReads data

DELETE
DML. Removes rows (supports WHERE). Can be rolled back, and triggers fire. Slower.
TRUNCATE
DDL. Removes all rows quickly, keeps the structure, and resets identity counters. No WHERE.
DROP
DDL. Removes the whole table: its structure, data and indexes.
Clause order: written vs executed
Written: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT
Executed: FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT
That's why WHERE can't use aggregates or SELECT aliases, but ORDER BY can.
Aggregates & NULL
COUNT, SUM, AVG, MIN and MAX ignore NULLs, except COUNT(*), which counts rows. NULL = NULL isn't true, so use IS NULL. Any arithmetic with NULL gives NULL. GROUP BY puts all NULLs into one group. Use COALESCE(x, 0) to replace NULLs.

Subqueries
A query inside another. Second-highest salary: SELECT MAX(salary) FROM Employee WHERE salary < (SELECT MAX(salary) FROM Employee). Operators: IN, EXISTS, ANY, ALL.
UNION vs UNION ALL
UNION removes duplicates. UNION ALL keeps them (and is faster). The columns must match in number and type. INTERSECT and EXCEPT/MINUS also exist.
View · Index
A view is a saved query, used like a virtual table. An index speeds up reads (usually a B+ tree) but slows writes. Clustered = sorts the table itself (one per table).

Handy operators: BETWEEN 10 AND 20 (inclusive) · IN (…) · LIKE 'A%' (% = any characters, _ = exactly one) · DISTINCT · ORDER BY salary DESC · LIMIT n / TOP n. A stored procedure is saved SQL code. A trigger runs automatically on INSERT, UPDATE or DELETE.

DB4
Reliability

Transactions, ACID & Concurrency

Atomicity

All or nothing. A transfer debits and credits, or neither happens.

Consistency

Moves from one valid state to another, and constraints hold.

Isolation

Concurrent transactions don't see each other's partial work.

Durability

Committed data survives crashes, using logs and disk writes.

ProblemWhat happensPrevented from
Dirty readReads data that another transaction hasn't committed yet (and may roll back)Read Committed
Non-repeatable readThe same row read twice gives different valuesRepeatable Read
Phantom readThe same query returns new or missing rowsSerializable
Lost updateTwo writes overlap and one is overwrittenLocking
DeadlockTwo transactions each wait for the other's lockDetection or timeouts, lock ordering

Isolation levels, from weakest to strongest: Read Uncommitted → Read Committed → Repeatable Read → Serializable. Transaction states: Active → Partially Committed → Committed / Failed → Aborted. Locks: shared (read) and exclusive (write).

Programming

  • Compiler = whole program first · interpreter = line by line · Java → bytecode → JVM
  • Java: int 4 bytes, char 2, long 8, double 8
  • Signed n-bit: −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1 · overflow wraps
  • Widening is automatic · narrowing needs a cast (truncates)
  • static local: initialised once and keeps its value
  • Stack = locals and calls · heap = malloc/new
  • p + 1 moves one element · *(a + i) == a[i]
  • Leak = never freed · dangling = points to freed memory
  • Address = base + i × size · row-major (i·cols + j)
  • strlen excludes \0 · sizeof includes it
  • Java Strings are immutable · use StringBuilder
  • 1 + 2 + "x" = "3x" · "x" + 1 + 2 = "x12"

DSA

  • Stack LIFO (calls, undo, DFS) · queue FIFO (BFS)
  • Circular rear = (rear + 1) mod n
  • Linked list: head insert O(1), access O(n)
  • In-order of a BST = sorted · pre = Root L R · post = L R Root
  • Max nodes 2ʰ⁺¹ − 1 · n nodes → n − 1 edges
  • Heap children 2i + 1, 2i + 2 · parent (i − 1)/2
  • Hash collisions: chaining / linear probing
  • Binary search needs sorted data · O(log n)
  • Merge always n log n · quick worst n² · insertion best n
  • Stable: bubble, insertion, merge, counting
  • Halving → log n · nested → n² · 2 branches → 2ⁿ
  • 2T(n/2) + n = n log n · T(n/2) + 1 = log n

DBMS

  • Degree = columns · cardinality = rows
  • PK = unique + not null · FK → another table's PK
  • Candidate = minimal super key
  • 1NF atomic · 2NF no partial · 3NF no transitive
  • DDL: CREATE, ALTER, DROP, TRUNCATE
  • DML: INSERT, UPDATE, DELETE · TCL: COMMIT, ROLLBACK
  • DELETE (WHERE, rollback) · TRUNCATE (all rows) · DROP (table)
  • Executed: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
  • COUNT(*) counts rows · COUNT(col) skips NULLs
  • INNER = matches · LEFT = all left rows · CROSS = m × n
  • UNION removes duplicates · UNION ALL keeps them
  • ACID · dirty / non-repeatable / phantom reads
