PART 1 · PSEUDOCODE

Reading & Tracing Code

Pseudocode is language-neutral, but it behaves like C or Java: integers truncate, characters are numbers, arrays start at 0, and operators follow C precedence. Learn these rules once and every question becomes mechanical.

Integer division
7 / 2 = 3, 2 / 5 = 0, -7 / 2 = -3 (truncates toward zero). If either side is a Float, the result keeps decimals: 7.0 / 2 = 3.5.
Characters
A Char is a small integer (its ASCII code): 'A' = 65, 'a' = 97, '0' = 48. 'A' + 1 = 66, which is 'B'. 'a' - 'A' = 32.
Integer storage
An Integer has limits (32-bit: about ±2.1 billion). Going past the maximum wraps around to negative (overflow). Assigning a decimal to an Integer truncates: Integer x = 9.8 gives 9.

Memory trick: Unary → Arithmetic (* / % then + −) → Shift → Relational → Equality → Bitwise (& ^ |) → Logical (&& ||) → Ternary → Assignment.

++ and -- (pre vs post)
b = a++ → b gets the old value, then a increases.
b = ++a → a increases first, then b gets the new value.
With a = 5: b = a++ gives b = 5, a = 6. c = ++a gives c = 7, a = 7.
Avoid reasoning about a++ + ++a in one statement. In C that's undefined behaviour, and well-formed exam questions avoid it.
Division & mod with negatives (C/Java)
Division truncates toward 0: -7 / 2 = -3, 7 / -2 = -3.
Mod takes the sign of the dividend (the left side): -7 % 2 = -1, 7 % -2 = 1.
Check: (a / b) * b + a % b == a.
Excel's MOD(−7, 3) = 2 and Python's −7 % 3 = 2 follow the divisor's sign instead. Pseudocode follows C/Java.
Short-circuit evaluation
In A && B, if A is false, B is never evaluated.
In A || B, if A is true, B is never evaluated.
This matters when B contains ++j or a function call: those side effects might never happen.
Truth values
In C-style pseudocode, any non-zero value is true and 0 is false. Comparisons give 1 or 0: (5 > 3) + (2 > 9) = 1 + 0 = 1. !5 = 0, !0 = 1.
Top 6 operator traps: ① x << 1 + 2 means x << 3 · ② x & 1 == 0 means x & 0 · ③ = inside if assigns (if (a = 0) is always false) · ④ integer / drops decimals before you multiply: (1 / 2) * 10 = 0 · ⑤ the sign of a negative mod · ⑥ skipped side effects in && and ||.

Powers of 2 to memorise

2⁰ = 12¹ = 22² = 42³ = 8
2⁴ = 162⁵ = 322⁶ = 642⁷ = 128
2⁸ = 2562⁹ = 5122¹⁰ = 10242¹⁶ = 65536

Octal groups bits in 3s and hex groups bits in 4s: 58 = 111 010 = 72₈ = 0011 1010 = 3A₁₆. In code, 0x marks hex and a leading 0 marks octal in C (010 = 8!).

Negative numbers: two's complement To get −x: invert all the bits of x, then add 1. In 8 bits, 5 = 00000101 → inverted 11111010 → +1 = 11111011 = −5. The leftmost bit is the sign (1 = negative). An 8-bit signed range is −128 to +127.
That's why ~x = −(x + 1): inverting the bits is "−x − 1". So ~5 = −6, ~0 = −1 and ~(−3) = 2.

Branching

Conditions & switch

Integer a = 5, b = 10
if (a > 3)
    if (b < 5) Print "X"
else Print "Y"   // pairs with the INNER if → prints Y
Dangling else
An else always belongs to the nearest unmatched if, whatever the indentation. Indentation is just decoration.
switch (k)            // k = 2
  case 1: s = s + 1
  case 2: s = s + 2    // enters here
  case 3: s = s + 3    // falls through!
          break
  default: s = 0
switch fall-through
Execution starts at the matching case and keeps going through the cases below until it reaches a break. With k = 2 and s = 0 at the start, s = 2 + 3 = 5. default runs only when nothing matches, or when it's reached by falling through.
Condition traps: if (x = 5) assigns 5, which is non-zero, so it's always true · if (a > b > c) compares (a > b), which is 0 or 1, against c · a semicolon right after if (…); makes an empty statement, so the next line always runs · in an else-if chain, only the first true branch runs.

Functions & Recursion

Every recursive function needs (1) a base case that stops it and (2) a recursive case that moves toward the base case. Each call gets its own copy of its local variables, stored on the call stack. Without a base case you get infinite recursion and a stack overflow.
Function f(Integer n)
    if (n == 0) return 0
    return n mod 10 + f(n / 10)
End Function
Print f(472)
Going down (calls)Coming back (returns)
f(472) = 2 + f(47)2 + 11 = 13
f(47) = 7 + f(4)7 + 4 = 11
f(4) = 4 + f(0)4 + 0 = 4
f(0) → base case0
Head vs tail printing
Print n; f(n−1) → prints on the way down: 3 2 1
f(n−1); Print n → prints on the way up: 1 2 3
With both: 3 2 1 1 2 3.
Branching recursion (two calls)
Draw a recursion tree. The number of calls in naive Fibonacci is C(n) = C(n−1) + C(n−2) + 1: C(5) = 15 and C(10) = 177. The values repeat, which is why memoisation helps.

Call by value vs reference
By value: the function gets a copy, so changes don't affect the caller (a swap(a, b) by value does nothing). By reference / pointer: changes affect the caller. In Java, primitives are copied, and for objects the reference is copied: the function can change the object's fields, but can't make the caller's variable point somewhere else.
Static / global variables in recursion are shared by all calls, unlike local variables. If a function does count = count + 1 on a global, count ends up as the total number of calls.

Arrays & Strings

Arrays
Fixed size, contiguous memory, 0-indexed. a[i] is O(1). The last index is n − 1. 2D arrays are stored row by row (row-major): m[i][j] is row i, column j. The main diagonal is m[i][i] and the anti-diagonal is m[i][n−1−i].
Strings
A sequence of characters, with s[0] first. In C a string ends with '\0', so char s[6] holds 5 letters. In Java, Strings are immutable, so methods return new strings.

The basics

Classes, Objects & Constructors

class Student {
    String name;          // attribute (state)
    int marks;
    Student(String n, int m) {   // constructor
        this.name = n; this.marks = m;
    }
    boolean passed() { return marks >= 40; } // method
}
Student s = new Student("Ravi", 72);  // object
Class vs Object
A class is a blueprint that defines state (fields) and behaviour (methods). An object is an instance created with new, which allocates memory on the heap. Many objects can come from one class.
Constructor
Same name as the class, no return type (not even void), runs automatically when new is called. If you write none, Java supplies a default no-argument constructor, but only if you write no constructors at all.
Constructor typeMeaning
Default (no-argument)No parameters. Fields get defaults: 0, false, null
ParameterisedTakes values to initialise the object
Copy constructorBuilds a new object from an existing one (explicit in C++, written by hand in Java)
Overloaded constructorsSeveral constructors with different parameter lists. this(…) calls another one
DestructorC++ only (~ClassName()). Java has garbage collection instead
this refers to the current object. Use it when a parameter has the same name as a field (this.name = name), or call this(…) from a constructor (it must be the first statement). Without this, a parameter shadows the field.

Abstraction: Abstract Classes & Interfaces

Abstraction means exposing what an object does and hiding how. You call car.start() without knowing about the engine's internals.

abstract class Shape {
    abstract double area();        // no body
    void describe() {             // concrete method
        System.out.print("Area = " + area());
    }
}
class Circle extends Shape {
    double r; Circle(double r){ this.r = r; }
    double area() { return 3.14 * r * r; }
}
interface Payable {
    int LIMIT = 1000;      // public static final
    void pay(int amt);     // public abstract
    default void info() {  // Java 8+

    }
}
class Card implements Payable {
    public void pay(int amt) { … }
}

Inheritance & Constructor Chaining

TypeShapeIn Java?

HierarchicalA → B, A → C✓

Why no multiple class inheritance? The diamond problem. If B and C both override A's m() and D extends both, which m() does D get? Java forbids it for classes. C++ allows it and solves it with virtual inheritance.
class A { A() { print("A "); } }
class B extends A { B() { print("B "); } }
class C extends B { C() { print("C"); } }
new C();   // prints: A B C
Constructor chaining
The first line of every constructor is an implicit super(). Constructors run from the top of the hierarchy down: parent before child. Use super(args) to call a parameterised parent constructor. It must be the first statement. If the parent has no no-argument constructor, the child must call super(args).
What is inherited?
Public and protected members (and default ones in the same package). Not private members (they exist but can't be accessed), and not constructors.
super
super.method() calls the parent's version. super.field accesses a parent field hidden by the child.
Initialisation order
Static blocks (once, at class load) → instance initialiser blocks → constructor body. Parent before child at each stage.

class Animal { void sound() { print("..."); } }
class Dog extends Animal {
    void sound() { print("Woof"); } }
Animal a = new Dog();  // upcasting (implicit)
a.sound();             // Woof → dynamic dispatch
The golden rule for output questions
Reference type decides what you're allowed to call, as well as fields and static methods.
Object type decides which overridden instance method actually runs.
So a.x uses Animal's field, but a.sound() uses Dog's method.
Overload resolution order: exact match → widening of primitives (int → long → float → double) → autoboxing (int → Integer) → varargs. So f(5.0f) with only f(int), f(long) and f(double) available calls f(double). Downcasting (Dog) a must be explicit, and throws ClassCastException if the object isn't really a Dog.

Keywords & relationships

static, final, Relationships & More

static belongs to the class, not to objects. One copy is shared by all objects (counters, constants). Static methods can't use this or call instance members directly. Call them as ClassName.method().
final: a final variable can't be reassigned · a final method can't be overridden · a final class can't be extended (for example, String).
RelationshipMeaningExample
Inheritance (is-a)A child is a specialised parentDog is an Animal
Association (uses-a)Objects know or use each other, with independent lifetimesTeacher ↔ Student
Aggregation (weak has-a)A whole contains parts that can exist aloneTeam has Players
Composition (strong has-a)The parts die with the wholeHouse has Rooms · Car has an Engine
Object class
The root of every Java class. It provides toString(), equals(), hashCode() and getClass().
== vs equals()
== compares references (same object?). equals() compares content, if the class overrides it, as String does.
Garbage collection
The JVM frees objects that are no longer referenced. You can't force it: System.gc() is only a request.
Coupling & cohesion
Good design has low coupling (few dependencies between classes) and high cohesion (each class has one focused job).
Exceptions (basics)
try → catch → finally. The finally block always runs (even after a return in try). Checked exceptions must be handled or declared.
OOP languages
Java, C++, C#, Python. C is procedural, not OOP. "Pure" OOP languages (like Smalltalk) treat everything as an object.

Pseudocode in 12 lines

  • Precedence: unary → * / % → + − → << >> → relational → == → & → ^ → | → && → || → ?: → =
  • x << 1 + 2 = x << 3 · x & 1 == 0 = x & 0
  • Integer / truncates toward 0 · % takes the sign of the left operand: −7 % 2 = −1
  • a++ uses the value then adds · ++a adds then uses
  • && / || short-circuit, so side effects may be skipped
  • ~x = −x − 1 · x<<n = x·2ⁿ · x>>n = x/2ⁿ · x^x = 0
  • x & (x−1) clears the lowest bit · x & 1 tests odd
  • else pairs with the nearest if · switch falls through until a break
  • for a to b runs b − a + 1 times · i *= 2 runs log₂n times · triangle loops run n(n+1)/2
  • Recursion: expand down, combine on the way up · printing after the call gives reverse order
  • Naive fib calls: C(n) = C(n−1) + C(n−2) + 1 · globals count calls
  • Arrays 0-indexed · 'A' = 65, 'a' = 97, '0' = 48 · call by value doesn't change the caller

OOPs in 12 lines

  • Encapsulation = hide data · Abstraction = hide implementation
  • Inheritance = is-a · Polymorphism = one interface, many forms
  • Overloading: same class, different parameters, compile time · return type alone isn't enough
  • Overriding: same signature, child class, run time · can't reduce access
  • Fields and static methods follow the reference type · instance methods follow the object type
  • Constructors: no return type, not inherited, can't be overridden, can be overloaded
  • Constructor order: parent → child · super() / this() must come first
  • Initialisation: static block (once) → instance block → constructor
  • Abstract class: can have a constructor and state, extend only one · Interface: constants only, implement many
  • Java: no multiple class inheritance (the diamond problem), so use interfaces
  • private < default < protected < public · final = no change, override or extend
  • Composition = part dies with the whole · Aggregation = part survives · == vs equals()
