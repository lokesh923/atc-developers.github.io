Know the round

The Coding Round

Three questions in 60 minutes: one DSA coding problem, one SQL query and one front-end task. You choose the order. Each answer is graded by hidden test cases, so partially correct code earns partial marks.

QuestionTime planWhat it looks like
C1 · DSA~25 minLeetCode Easy to Medium: arrays, strings, hashing, two pointers, basic recursion, sorting-based problems, number logic. Languages: Java, Python, C++, C#, .NET (some candidates only saw Java, Python and C#).
C2 · SQL~15 minOne query on 1–3 tables: SELECT/WHERE/ORDER BY/GROUP BY/HAVING, joins (main focus), aggregates, DISTINCT, LIMIT, basic subqueries. Exact column aliases are required.
C3 · Frontend~20 minComplete or fix a given HTML/CSS/JS template (HackerRank React-certification style): DOM manipulation, events, form validation, CSS selectors and flexbox, toggling classes, React and Vue basics.
How the coding editor works
Pick a language → a template appears (often a function to complete, sometimes a full program). Run / Compile & Run uses the sample input; Submit runs all test cases, including hidden ones. You can usually submit more than once; the last submission counts.
Important for Java usersThe template may contain a line like throw new Exception(...) or throw new UnsupportedOperationException(). Comment it out or delete it before running, or your code will fail even if the logic is correct. Also keep the class name the template uses (often Main or Solution).
Scoring mindsetHidden tests check edge cases: empty input, one element, all equal values, negative numbers, very large values. A simple solution that handles every edge case beats a clever one that crashes on N = 1.

Solving a DSA problem in 6 steps

1 Read twice→2 Note input limits→3 Work 1 example by hand→4 Pick a pattern→5 Code + run samples→6 Test edge cases, submit
Pattern hints in the wording
"pair / two numbers add up to" → hashing or two pointers · "longest / shortest substring" → sliding window · "sorted array" → two pointers or binary search · "count / frequency / duplicate / first unique" → HashMap · "all combinations / subsets" → recursion · "overlapping intervals" → sort first.
Edge-case checklist
N = 0 or 1 · all elements equal · negative numbers and zero · duplicates · already sorted / reverse sorted · maximum N (time) · values near 109 (use long) · empty string or spaces only · upper/lower case.
When stuck
Write the brute force (nested loops) and submit it: it passes the small tests. Then optimise with a HashMap, sorting or two pointers. Print intermediate values to debug, and remove the prints before submitting.
Output format is part of the answerPrint exactly what is asked: no extra text like "Answer:", no trailing spaces where a single space is expected, and the exact case (YES vs Yes). When a function is required, return the value instead of printing it.

PART A · BACKEND DSA CODING (C1)

Data Structures & Algorithms

Input handling, complexity, then the eight patterns that cover almost every Easy–Medium question, each with solved, tested programs in Java and Python.

A1
Read input, print output

Input / Output Templates

Some questions give a function to complete (the platform reads input for you). Others expect a full program that reads from standard input (the keyboard) and prints to standard output. Learn one reading template by heart in your language. Each one below reads N, then N numbers, then a word.

Function-style template (very common)
You only write the body, for example public static int secondLargest(int[] arr) or def second_largest(arr):. Return the answer; do not print it and do not read input yourself. Keep the given signature unchanged.
Reading tips
Java: Scanner is simple but slow for 105+ numbers, so use BufferedReader. Mixing nextInt() and nextLine() leaves a newline behind, so call an extra nextLine(). Python: input().split() per line, or sys.stdin.read().split() for everything at once.
A2
Will it be fast enough?

Complexity in Practice

Online judges allow roughly 108 simple operations per second (Python is about 10× slower than Java/C++). Use the input limit to choose the algorithm before you code:

Max NNeeded complexityTypical approach
N ≤ 10–20O(2N), O(N!)Recursion, generate all subsets/permutations
N ≤ 1,000O(N²)Two nested loops, brute force over pairs
N ≤ 105 – 106O(N log N) or O(N)Sorting, HashMap, two pointers, sliding window, prefix sums
N ≤ 107O(N)One pass, sieve
N ≤ 1018O(log N) or O(√N)Math, binary representation, digit loops, GCD
Integer overflow
Java/C++/C# int holds about ±2.1 × 109. Sums of many values, products and factorials need long / long long. Python integers never overflow.
Hidden O(N) costs
String += in a loop (use StringBuilder / join), list.remove(x), x in list (use a set), and s.substring inside a loop all cost O(N) each time.
Space
A HashMap or extra array of N items is fine for N ≤ 106. Deep recursion (N > ~104) can overflow the stack, so prefer loops then.
A3
The most common topic

Arrays

Core moves
Traverse once and keep running values (max, min, sum, count) · prefix sums pre[i] = pre[i-1] + a[i], so a range sum is pre[r] − pre[l−1] · reverse a range with two indices · in-place rewrite with a write pointer · Kadane for the best subarray.
Questions you will meet
Second largest / smallest · max subarray sum · rotate by K · move zeros · missing number (n(n+1)/2 − sum) · leaders in an array · equilibrium index (prefix sums) · stock buy/sell once (track the min price so far).
A4
Characters and words

Strings

Core moves
Loop over characters · count with int[26] (c - 'a') or a HashMap · two pointers from both ends (palindromes) · split into words · build output with StringBuilder (Java) or "".join(list) (Python). Java Strings are immutable; compare them with .equals(), never ==.
Questions you will meet
Palindrome · anagram · first unique character · reverse words · compress (aaabb → a3b2) · count vowels/consonants · toggle case · remove duplicates · longest common prefix · check rotation (s2 inside s1 + s1).
A5
O(1) lookups

Hashing

The idea
A HashMap (dict) maps a key to a value and a HashSet (set) stores unique keys. Insert, lookup and delete take O(1) on average. Turn "have I seen this before?" from an O(N) search into an O(1) check. That usually turns O(N²) into O(N).
Typical uses
Frequency counting · duplicates (set size vs list size) · Two Sum (complement lookup) · first non-repeating · group anagrams (key = sorted word) · longest consecutive sequence · subarray sum = K (map of prefix sums).
A6
Two indices instead of two loops

Two Pointers & Sliding Window

Two pointers
(a) Opposite ends on a sorted array: pair sum, palindrome check, container problems. (b) Same direction (read / write pointer): remove duplicates, move zeros, partition. Each pointer moves at most N times, so the total is O(N).
Sliding window
A window [left, right] over an array or string. Grow right; when the window breaks a rule (repeat character, sum too big), shrink from left. Used for longest/shortest substring or subarray, max sum of K consecutive elements, and at most K distinct characters.
A7
Order makes it easy

Sorting-Based Problems

Why sort?
After sorting, equal items are neighbours (duplicates, grouping), overlapping intervals are adjacent, and two pointers work. Built-in sort is O(N log N): Java Arrays.sort / Collections.sort, Python sorted() / list.sort(), C++ sort(), C# Array.Sort.
Custom order
Java: list.sort((a, b) -> ...) returns negative / zero / positive; use Integer.compare(a, b) instead of a - b for large values. Python: sorted(x, key=lambda v: (-count[v], v)) sorts by count descending, then value ascending.
A8
A function that calls itself

Recursion & Backtracking

Two parts, always
(1) Base case: the smallest input, answered directly; without it the recursion never stops (StackOverflowError). (2) Recursive case: solve a smaller version and combine.
Memoization
If the same arguments repeat (Fibonacci, stairs, grid paths), store the results in an array or map. The time drops from exponential to O(number of different states).
Backtracking
Choose → recurse → undo the choice. Generates subsets, permutations and combinations: O(2N) or O(N!), so only for small N (≤ 10–20).
A9
Math-flavoured problems

Number Logic

Digit tricks
Last digit: n % 10 · remove the last digit: n / 10 (Python //) · digit count: loop or len(str(n)) · reverse: rev = rev * 10 + n % 10 · palindrome number: reversed == original · sum of digits, Armstrong, strong, perfect and Harshad numbers all use the same loop.
Number theory essentials
Prime check: divide only up to √n · many primes: sieve · GCD: Euclid · LCM = a / gcd × b · even/odd: n % 2 or n & 1 · power of two: n > 0 && (n & (n − 1)) == 0 · fast power by squaring.

PART B · DATABASE SQL (C2)

SQL for the Coding Round

One query, about 15 minutes. Joins are the main focus, together with GROUP BY/HAVING, aggregates, DISTINCT, LIMIT and simple subqueries. Triggers, window functions and other advanced SQL are not asked.

B1
Read it like the database does

Query Skeleton & Execution Order

SELECT   columns, aggregates AS alias
FROM     table1 t1
JOIN     table2 t2 ON t1.key = t2.key
WHERE    row conditions
GROUP BY grouping columns
HAVING   group conditions
ORDER BY columns DESC
LIMIT    n;
FROM / JOIN→WHERE→GROUP BY→HAVING→SELECT→ORDER BY→LIMIT
Consequences of the order
WHERE runs before grouping, so COUNT() cannot go in WHERE; filter groups with HAVING. SELECT aliases can be used in ORDER BY but not in WHERE.
Aggregates and NULL
COUNT(*) counts rows; COUNT(col), SUM, AVG, MIN and MAX ignore NULLs. Test with IS NULL, never = NULL.
Aliases
COUNT(*) AS total. An alias with a space needs quotes: AS "First Name", or backticks in MySQL. The grader compares column names, so copy them exactly.
B2
The main focus

Joins

INNER JOIN
Only rows that match in both tables
LEFT JOIN
All left rows, plus matches (NULL where there is no match)
RIGHT JOIN
All right rows, plus matches from the left
SELF JOIN
A table joined with itself (employee ↔ manager)

Every SQL example below runs on these two tables. Arjun has no department and Finance has no employees, so you can see what each join does with unmatched rows.

Learn these and most SQL questions are familiar

Ten Patterns with Real Output

Common mistakes that fail hidden testsINNER JOIN where "all customers / all departments" are required (use LEFT JOIN) · COUNT(*) after a LEFT JOIN (counts 1 instead of 0, so use COUNT(child.id)) · forgetting DISTINCT when one row can match many · >= vs > (read "more than" and "at least" carefully) · wrong ORDER BY direction, or no tie-breaker · alias spelled differently from the question · LIKE 'A%' (starts with) vs '%A%' (contains).

PART C · FRONTEND (C3)

HTML, CSS, JavaScript, React & Vue

You get a template with HTML, CSS and JS tabs (or a React/Vue component) and a list of objectives. Hidden tests open your page, click, type and check the DOM and the computed CSS.

C1
What the grader checks

How Front-end Tasks Are Graded

Exact selectors
Tests find elements by the id, class and text given in the question. id="p" vs id="para", or "Account Alert" vs "Account alert", is a fail even if the page looks right.
Computed style
CSS is checked through the browser's computed values: #71E5F4 becomes rgb(113, 229, 244), and a width becomes "120px". Any valid CSS that produces the value passes.
Behaviour
Tests click buttons and type into inputs, then check the result. "Remove" means element.remove(), not display:none. Read every constraint.

Final Cheat Sheet

DSA

  • Comment out throw new Exception in Java templates
  • Return (function template) vs print (full program)
  • Read the limits: 105 needs O(N log N) or better
  • Pair/complement → HashMap · sorted → two pointers
  • Substring/subarray "longest" → sliding window
  • Frequency → int[26] or Counter
  • Intervals → sort by start, then merge
  • Recursion: base case first; memoize repeats
  • Use long for sums and products
  • Test N = 1, all equal, negatives, empty
  • Exact output format, no debug prints

SQL

  • Order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
  • Aggregate filter → HAVING, never WHERE
  • "All X even without Y" → LEFT JOIN + COUNT(y.id)
  • "No matching rows" → LEFT JOIN … WHERE y.id IS NULL
  • Manager/employee → self join with two aliases
  • Second highest → MAX(...) WHERE < (SELECT MAX…)
  • Top per group → correlated subquery with MAX
  • Duplicates → GROUP BY … HAVING COUNT(*) > 1
  • Copy aliases and column order exactly
  • DISTINCT when one row can match many

Frontend

  • Copy ids, classes and texts exactly
  • querySelector → addEventListener → change the DOM
  • classList.add / remove / toggle; className replaces all
  • textContent for text; value for inputs
  • Forms: e.preventDefault() on submit
  • Remove means el.remove()
  • Run filters/counters once on load too
  • React: useState + setter, className, key in map
  • Vue: v-model, v-for + :key, v-if, computed, :class
  • No red errors in the Console
