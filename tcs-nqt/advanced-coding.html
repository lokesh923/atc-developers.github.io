Programming Fundamentals and Input/Output

Every coding problem starts with reading input correctly and ends with printing exactly the required output. Many solutions fail not because the logic is wrong but because of a mistake in reading, data types or the output format.

Start from zero

Anatomy of a problem

A TCS NQT coding problem has a statement, an input format, an output format, constraints, one or two sample tests and many hidden tests. Your code is judged on the hidden tests. Passing the sample is only the start.

Reading input

Python: n = int(input()) reads one integer; a = list(map(int, input().split())) reads a line of integers. C++: cin >> n; and a loop to read an array. Java: Scanner sc = new Scanner(System.in); then sc.nextInt(). For many test cases the first line is T and the rest repeats T times.
The parts of an NQT coding problem

Data types and overflow

In C, C++ and Java, int holds about ±2.1 × 10⁹. Use long long (C++) or long (Java) when sums or products can reach 10¹⁰ or more. Python integers are unbounded, so overflow is not a problem there. Many problems ask for an answer modulo 10⁹ + 7 to keep numbers small.

Operators you must know

Integer division // (Python) or / on ints (C++); remainder %. Python's % gives a non-negative result for a positive divisor even if the dividend is negative, but C++ can give a negative remainder. Comparison and logical operators: ==, !=, and/or/not (Python) or && || ! (C++).

Loops and patterns

Use a for loop when the count is known and a while loop otherwise. Patterns (triangles, pyramids) are nested loops: the outer loop is the row and the inner loop prints the columns. Always check the output format: spaces and line breaks matter.

Output rules

Print exactly what is asked. Capital letters for YES and NO if the sample uses them. No extra text such as 'Answer:'. For several values on one line use spaces; for several test cases use one line per case unless told otherwise.

Formula and rule box

  • int ≈ ±2.1 × 10⁹; long long ≈ ±9.2 × 10¹⁸
  • Use long long when a product can exceed 2 × 10⁹
  • (a × b) mod m = ((a mod m) × (b mod m)) mod m
  • Multiple tests: read T, then loop T times
  • Digit sum: repeat n % 10 and n // 10
  • Leap year: divisible by 4 and (not by 100 or divisible by 400)

Step-by-step method

  1. Read the statement, input format and constraints.
  2. Choose data types from the constraints.
  3. Write the logic for the sample and trace it by hand.
  4. Test edge cases (0, 1, maximum, negative values) before submitting.

Solved examples

Example 1. Read T test cases. For each, read two integers and print their sum.
Solution: Read T first, then loop T times, read a and b and print a + b. In C++ use long long to be safe.
Python t = int(input()) for _ in range(t): a, b = map(int, input().split()) print(a + b)
C++ #include <iostream> using namespace std; int main() { int t; cin >> t; while (t--) { long long a, b; cin >> a >> b; cout << a + b << "\n"; } return 0; }
Sample input: 3 / 1 2 / 10 20 / -5 5   Sample output: 3 / 30 / 0
Answer: Output: 3 / 30 / 0
Example 2. Print a right triangle of stars of height n.
Solution: Row i prints i stars. A string multiplied by a number repeats the string.
Python n = int(input()) for i in range(1, n + 1): print('*' * i)

Answer: Output: * / ** / *** / ****
Example 3. Print the numbers 1 to n, but 'Fizz' for multiples of 3, 'Buzz' for multiples of 5 and 'FizzBuzz' for multiples of both, separated by spaces.
Solution: Check the multiple of 15 first, otherwise 3 and 5 will catch it early.

Example 4. Read a and b (each up to 10⁹). Print (a × b) mod 1,000,000,007.
Solution: The product reaches 10¹⁸. In C++ it needs long long; in Python it is automatic. Take the modulo after multiplying.
Python a, b = map(int, input().split()) MOD = 10**9 + 7 print(a * b % MOD)

Sample input: 1000000000 1000000000   Sample output: 49
Answer: Output: 49

Shortcuts

  • Python's print(*list) prints items separated by spaces.
  • Use long long by default in C++ when unsure.
  • Trace the sample by hand before running.

Common mistakes

  • Forgetting to read T test cases.
  • Using int where the answer needs long long.
  • Printing extra spaces or text.

Time Complexity and Constraints

A correct but slow solution scores zero on large hidden tests. Complexity tells you in advance whether your idea will finish in time. Read the constraints before writing any code.

Start from zero

What Big-O means

Big-O describes how the running time grows when the input size n grows, ignoring constants. A single loop over n items is O(n). A loop inside a loop is O(n²). Halving the range each step (binary search) is O(log n). Sorting is O(n log n).

How many operations fit in the time limit

A typical judge allows about 10⁸ simple operations per second in C++ and about 10⁷ in Python. So with n = 10⁵, an O(n²) solution does 10¹⁰ operations and fails, but O(n log n) does under 2 × 10⁶ and passes.
Growth curves of common complexities

Match constraints to algorithms

Use the table: n ≤ 10 allows brute force over permutations; n ≤ 20 allows subsets; n ≤ 500 allows O(n³); n ≤ 5,000 allows O(n²); n ≤ 10⁵ needs O(n log n); n ≤ 10⁷ needs O(n); n up to 10¹⁸ needs O(log n) such as binary search or fast power.

Cost of common operations

List append O(1); list.pop(0) or insert at the front O(n); dictionary/set lookup O(1) on average; sorted() O(n log n); string concatenation in a loop can be O(n²) (use join); slicing a list copies it (O(n)).

Space complexity

Extra memory used: O(1) for a few variables, O(n) for an extra array. A 2D table of 10⁴ × 10⁴ is too large; reduce it to one or two rows when possible.

Optimise step by step

First write a brute force that is surely correct. Then find the repeated work: nested loops that recompute sums (use prefix sums), searches (use a set or binary search) or recursion that repeats states (use memoisation).
Match the constraint to an algorithm

Formula and rule box

  • ≈10⁸ operations/second (C++), ≈10⁷ (Python)
  • n ≤ 10⁵ → O(n log n) or better
  • n ≤ 5,000 → O(n²) is fine
  • n ≤ 20 → O(2ⁿ) is fine
  • sort = O(n log n); binary search = O(log n)
  • dict/set lookup = O(1) average

Step-by-step method

  1. Read the constraint on n.
  2. Compute operations for your idea (n² for nested loops).
  3. If too slow, find the repeated work.
  4. Replace it with a prefix sum, a hash map, sorting or binary search.

Solved examples

Example 1. Given an array and a target, print YES if two different elements sum to the target. First line n, second line the array, third line target.
Solution: Brute force checks all pairs in O(n²). Using a set of seen values finds the partner in O(1), giving O(n) overall.
Python n = int(input()) a = list(map(int, input().split())) target = int(input()) seen = set() found = False for x in a: if target - x in seen: found = True break seen.add(x) print('YES' if found else 'NO')
C++ #include <iostream> #include <unordered_set> using namespace std; int main() { int n; cin >> n; long long a[100000]; for (int i = 0; i < n; i++) cin >> a[i]; long long target; cin >> target; unordered_set<long long> seen; bool found = false; for (int i = 0; i < n; i++) { if (seen.count(target - a[i])) { found = true; break; } seen.insert(a[i]); } cout << (found ? "YES" : "NO") << endl; return 0; }
Sample input: 4 / 2 7 11 15 / 9   Sample output: YES
Answer: Output: YES
Example 2. Print the sum of all subarray sums of an array of length n (n up to 10⁵).
Solution: Each element a[i] appears in (i+1) × (n−i) subarrays. So the total is the sum of a[i] × (i+1) × (n−i), computed in O(n) instead of O(n³).
Python n = int(input()) a = list(map(int, input().split())) total = 0 for i, x in enumerate(a): total += x * (i + 1) * (n - i) print(total)
Sample input: 3 / 1 2 3   Sample output: 20
Answer: Output: 20
Example 3. Count primes up to n (n up to 10⁶).
Solution: Checking every number by trial division is too slow. A sieve marks multiples of each prime in O(n log log n).
Python n = int(input()) is_p = [True] * (n + 1) is_p[0] = False if n >= 1: is_p[1] = False i = 2 while i * i <= n: if is_p[i]: for j in range(i * i, n + 1, i): is_p[j] = False i += 1 print(sum(is_p))
Sample input: 100   Sample output: 25
Answer: Output: 25

Shortcuts

  • Memorise the constraint-to-complexity table.
  • If n ≤ 10⁵, avoid double loops over the array.
  • Use sets and dictionaries to replace inner loops that search.

Common mistakes

  • Writing nested loops when n is 10⁵ or larger.
  • Rebuilding strings with + in a long loop.
  • Using list.pop(0) in a loop.

Arrays

Arrays are the most common topic in the coding round. Most problems ask you to traverse the array once, remember something while you go, and print the result.

Start from zero

What an array is

An array is a list of items stored in order, each with an index starting at 0. Access by index is O(1). Traversal visits each item once: O(n). In Python the same structure is a list.

Traversal patterns

Single pass for sum, maximum, minimum and counting. Two passes when you need a total first and then a comparison. Keep running variables (best so far, count so far) instead of storing everything.
Array rotation and prefix sums

Prefix sums

Build P where P[i] is the sum of the first i elements. Then the sum of elements l to r is P[r + 1] − P[l] in O(1). This turns many range-sum queries from O(n) each into O(1) each.

Kadane's algorithm

Maximum sum of a contiguous subarray in one pass: keep a running sum that restarts at 0 when it becomes negative, and track the best sum seen. Handle the all-negative case by starting with the first element.

Rotation and reversal

Rotate left by k: a[k:] + a[:k] after k %= n. Reverse: a[::-1]. For in-place O(1)-space rotation, reverse the whole array and then the two parts.

Duplicates, missing numbers, frequency

A set tells you if there is a duplicate. For numbers 1 to n with one missing, the answer is n(n + 1)/2 − sum(array). A dictionary or counter array counts frequencies. Sorting first often simplifies pairing problems.

Formula and rule box

  • P[i] = a[0] + … + a[i−1]; sum(l..r) = P[r+1] − P[l]
  • Kadane: cur = max(x, cur + x); best = max(best, cur)
  • Missing number from 1..n: n(n+1)/2 − sum
  • Rotate left by k: a[k:] + a[:k] (k %= n)
  • Sum of first n numbers: n(n+1)/2

Step-by-step method

  1. Decide: single pass, prefix sum, sorting or hashing?
  2. Track the running value (sum, best, count).
  3. Handle n = 1 and all-negative or all-equal arrays.
  4. Check indices (off-by-one) on the sample.

Solved examples

Example 1. Rotate an array left by k positions. Print the new array.
Solution: Reduce k modulo n, then join the slice from k to the end with the slice before k.
Python n, k = map(int, input().split()) a = list(map(int, input().split())) k %= n print(*(a[k:] + a[:k]))
C++ #include <iostream> #include <vector> using namespace std; int main() { int n, k; cin >> n >> k; vector<int> a(n); for (auto &x : a) cin >> x; k %= n; for (int i = 0; i < n; i++) cout << a[(i + k) % n] << (i + 1 < n ? " " : "\n"); return 0; }
Sample input: 5 2 / 1 2 3 4 5   Sample output: 3 4 5 1 2
Answer: Output: 3 4 5 1 2
Example 2. Print the maximum sum of a contiguous subarray.
Solution: Kadane's algorithm: extend the running sum or restart at the current element.
Python n = int(input()) a = list(map(int, input().split())) cur = best = a[0] for x in a[1:]: cur = max(x, cur + x) best = max(best, cur) print(best)
C++ #include <iostream> #include <algorithm> using namespace std; int main() { int n; cin >> n; long long a, cur, best; cin >> a; cur = best = a; for (int i = 1; i < n; i++) { cin >> a; cur = max(a, cur + a); best = max(best, cur); } cout << best << endl; return 0; }
Sample input: 9 / -2 1 -3 4 -1 2 1 -5 4   Sample output: 6
Answer: Output: 6
Example 3. Answer q range-sum queries. Input: n, the array, q, then q lines with l and r (1-indexed).
Solution: Build prefix sums once. Each query is P[r] − P[l − 1].
Python n = int(input()) a = list(map(int, input().split())) P = [0] for x in a: P.append(P[-1] + x) q = int(input()) for _ in range(q): l, r = map(int, input().split()) print(P[r] - P[l - 1])
Sample input: 5 / 1 2 3 4 5 / 2 / 1 3 / 2 5   Sample output: 6 / 14
Answer: Output: 6 / 14
Example 4. An array of n − 1 distinct numbers from 1 to n has one number missing. Find it.
Solution: The total of 1 to n is n(n + 1)/2. Subtract the array's sum.
Python n = int(input()) a = list(map(int, input().split())) print(n * (n + 1) // 2 - sum(a))
Sample input: 5 / 1 2 4 5   Sample output: 3
Answer: Output: 3

Shortcuts

  • Use prefix sums whenever you see many range queries.
  • Kadane works in one pass and O(1) space.
  • Sort when the problem is about pairs, gaps or the k-th element.

Common mistakes

  • Starting Kadane with 0 and failing for all-negative arrays.
  • Forgetting k %= n in rotation.
  • Off-by-one in prefix sum queries.

Strings

Strings are arrays of characters, and string problems are about scanning, counting and comparing. Most solutions use one of four tools: two pointers, a frequency count, a stack or a simple pass with a running state.

Start from zero

Basics

A string is indexed from 0. In Python strings are immutable: s[i] = 'a' is not allowed, so build a new string or use a list of characters. Useful methods: s.lower(), s.upper(), s.isalpha(), s.isdigit(), s.split(), ' '.join(list), s[::-1] for reversing.

Palindromes

A string equal to its reverse. Compare s with s[::-1], or use two pointers moving inwards. For problems that ignore case and punctuation, first keep only letters and digits and convert to lower case.
Two pointers on a palindrome

Frequency and anagrams

Count characters with a dictionary or a 26-slot array. Two words are anagrams if their counts are equal (or their sorted letters are equal). The first non-repeating character is found by counting once and scanning again.

Run-length compression and parsing

Scan the string, count how many equal characters are in a row, and output the character with the count. Parsing numbers from text: loop over characters and build the number while you see digits.

Substrings and subsequences

A substring is contiguous; a subsequence keeps order but may skip. Count of substrings of length n is n(n + 1)/2. For longest substring problems use a sliding window.

Common pitfalls

Strings with spaces: use input() rather than split. Case: 'A' ≠ 'a'. Empty strings. Python string concatenation inside a long loop is slow; collect pieces in a list and join once.

Formula and rule box

  • s[::-1] reverses a string
  • Anagram ⇔ equal character counts
  • Number of substrings = n(n + 1)/2
  • ord('a') = 97; ord(c) − 97 gives 0–25
  • Palindrome: s == s[::-1]
  • Join pieces: ''.join(list)

Step-by-step method

  1. Decide whether you need counting, two pointers or a scan.
  2. Normalise (case, spaces) if the problem requires it.
  3. Handle empty and single-character strings.
  4. Print in the exact format (YES/NO or the string).

Solved examples

Example 1. Print YES if the string is a palindrome ignoring case and non-alphanumeric characters, else NO.
Solution: Clean the string, then compare it with its reverse.
Python s = input() t = ''.join(c.lower() for c in s if c.isalnum()) print('YES' if t == t[::-1] else 'NO')

"YES" : "NO") << endl; return 0; }

Solution: Sort the letters of both words and compare, or compare frequency counts.

Example 3. Compress a string with run-length encoding: aaabbc becomes a3b2c1.
Solution: Scan with a counter. When the character changes, output the previous character and its count.
Python s = input().strip() out = [] i = 0 while i < len(s): j = i while j < len(s) and s[j] == s[i]: j += 1 out.append(s[i] + str(j - i)) i = j print(''.join(out))

Shortcuts

  • sorted(a) == sorted(b) is the quickest anagram test.
  • Use a dictionary or collections.Counter for frequency.
  • isalnum() filters letters and digits.

Common mistakes

  • Forgetting to ignore case when the problem says to.
  • Using split() on a line with spaces you need to keep.
  • Building long strings with += inside a loop in Python.

Math and Number Theory

Number problems appear in almost every test. The tools are few: divisibility, the greatest common divisor, primes, fast exponentiation and digit manipulation.

Start from zero

Prime numbers

A prime has exactly two factors. To test n, try divisors from 2 up to √n; if none divides n, it is prime (n > 1). To list all primes up to n use the sieve of Eratosthenes: start from 2, cross out its multiples, then the next uncrossed number, and so on.

GCD and LCM

Euclid's algorithm: gcd(a, b) = gcd(b, a mod b), stopping when b is 0. LCM(a, b) = a × b / gcd(a, b). Python has math.gcd. For several numbers fold the function over the list.
The sieve of Eratosthenes up to 30

Divisors and factorisation

Factors come in pairs (d, n/d), so loop d from 1 to √n. The number of divisors comes from the prime factorisation: if n = p^a × q^b then divisors = (a + 1)(b + 1). A perfect number equals the sum of its proper divisors (6, 28, 496).

Digits and number properties

Use n % 10 for the last digit and n // 10 to remove it. Armstrong numbers equal the sum of their digits each raised to the number of digits (153 = 1³ + 5³ + 3³). A palindromic number reads the same reversed.

Fast exponentiation

To compute aᵇ mod m quickly use squaring: if b is even, a^b = (a²)^(b/2); if b is odd, a^b = a × a^(b−1). In Python use pow(a, b, m). This runs in O(log b).

Base conversion and other formulas

Decimal to binary: repeatedly divide by 2 and read the remainders backwards; Python: bin(n). Fibonacci: F(n) = F(n−1) + F(n−2). Trailing zeros in n! = n//5 + n//25 + n//125 + …

Formula and rule box

  • Prime test: check divisors up to √n
  • gcd(a, b) = gcd(b, a mod b)
  • lcm(a, b) = a × b / gcd(a, b)
  • pow(a, b, m) computes a^b mod m
  • Divisors of p^a q^b: (a + 1)(b + 1)
  • Trailing zeros of n! = n//5 + n//25 + n//125 + …
  • Sum 1..n = n(n + 1)/2

Step-by-step method

  1. Identify the property (prime, divisor, digit, power).
  2. Choose the standard routine (√n loop, Euclid, sieve, fast power).
  3. Check the constraint to pick the right efficiency.
  4. Test on 0, 1, 2 and a large value.

Sorting and Searching

Sorting arranges data so that comparing, pairing and searching become easy. Binary search then finds items in a sorted list in logarithmic time. Together they solve a large share of medium problems.

Start from zero

Sorting in practice

Use the built-in sort: a.sort() or sorted(a) in Python, sort(a.begin(), a.end()) in C++. Both run in O(n log n). Know bubble, selection and insertion sort for theory (O(n²)) and merge sort and quick sort (O(n log n)).

Custom ordering

Sort by a key: sorted(students, key=lambda x: (-x[1], x[0])) sorts by marks descending, then by name ascending. In C++ pass a comparator function. Sorting by multiple keys is a favourite question.
Binary search halves the range

Binary search

On a sorted array keep a range [lo, hi]. Look at the middle: if it equals the target, done; if the target is larger, move lo to mid + 1; otherwise move hi to mid − 1. Each step halves the range, so it needs about log₂ n steps.

Lower bound and counting

The lower bound is the first index whose value is ≥ x. Python: bisect.bisect_left(a, x). The count of x in a sorted array = bisect_right − bisect_left.

Searching on the answer

When 'the smallest value that works' is monotone (if x works, x + 1 works), binary search the answer itself and test each candidate with a simple check. This solves problems such as the minimum capacity or the smallest time.

Rotated sorted arrays

A sorted array rotated at some point still has one sorted half in every range. Compare the middle with the ends to decide which half is sorted and whether the target lies in it.

Formula and rule box

  • Sorting: O(n log n)
  • Binary search: O(log n)
  • mid = lo + (hi − lo) // 2
  • count(x) = bisect_right − bisect_left
  • Sort key: (−marks, name) for marks descending
  • Searching on the answer: check(mid) is monotone

Step-by-step method

  1. Is the data sorted or can you sort it?
  2. Pick key and order for sorting.
  3. For search use binary search with a clear loop invariant.
  4. Test with a single element and a target that is absent.

Hashing, Sets and Maps

A hash map or set answers 'have I seen this before?' in constant time. It turns many O(n²) pair-searching problems into O(n) problems, which is why hashing shows up so often.

Start from zero

Sets and dictionaries

A set stores unique values and supports fast membership tests (x in s). A dictionary stores key–value pairs (d[key] = value). In C++ use unordered_set and unordered_map (or set and map if you need sorted order).

Frequency maps

Count how often each value appears: d[x] = d.get(x, 0) + 1 or collections.Counter(a). Most problems about duplicates, majorities and anagrams are frequency problems.
Two-sum with a hash map

Two-sum and complements

For each element x, ask whether target − x has been seen. Store each element after the check so you do not pair an element with itself. One pass, O(n).

Prefix sums with a map

To count subarrays with sum K, keep a map from prefix sum to how many times it has occurred. At each position, add the count of (current prefix − K). This runs in O(n).

Grouping

Group items by a computed key: for anagram groups use the sorted word as the key. Use a dictionary of lists.

Longest consecutive sequence

Put all numbers in a set. For each number x with no x − 1 in the set, count up x + 1, x + 2 … in the set. Total time O(n).

Formula and rule box

  • Membership in set/dict: O(1) average
  • Frequency: d[x] = d.get(x, 0) + 1
  • Two-sum: look for target − x in seen
  • Subarray sum K: count[prefix − K]
  • Group key for anagrams: sorted(word)
  • Counter(a).most_common(1) gives the most frequent item

Step-by-step method

  1. Ask what you want to look up quickly.
  2. Choose set (presence) or dictionary (count, index).
  3. Decide the key (value, prefix sum, sorted word).
  4. Update the map after querying it.

Two Pointers and Sliding Window

These two patterns replace nested loops with a pair of moving indices. They solve many 'pair', 'subarray' and 'longest substring' problems in O(n).

Start from zero

Two pointers on a sorted array

Place one pointer at the start (i) and one at the end (j). If a[i] + a[j] is too small, move i right; if too large, move j left. This finds a pair with a given sum in O(n) after sorting.

Same-direction pointers

A slow pointer marks the next free spot and a fast pointer scans. Removing duplicates from a sorted array in place uses this pattern: the fast pointer finds a new value and the slow pointer stores it.
A sliding window of size 3

Fixed-size window

For the maximum sum of k consecutive elements, compute the first window's sum, then slide: add the incoming element and subtract the outgoing element. Total O(n).

Variable-size window

Expand the right end, and shrink the left end while the window breaks the rule. Used for the longest substring without repeats, the smallest subarray with sum ≥ S and the longest subarray with at most k distinct values.

When it works

Sliding window needs a 'monotone' rule: adding elements only makes the property harder (or easier), so you can move the left end only forward. For arrays with negative numbers and a sum target, use a prefix-sum map instead.

Formula and rule box

  • Pair sum on sorted array: i from the left, j from the right
  • Window sum: new = old + a[right] − a[left]
  • Longest unique substring: move left past the last duplicate
  • Time: O(n) because each pointer moves at most n times
  • Smallest subarray with sum ≥ S: shrink while sum ≥ S

Step-by-step method

  1. Check if the array is sorted (or can be sorted).
  2. Pick the pattern: opposite ends, slow–fast or window.
  3. Define what moves the left and right pointers.
  4. Update the answer at each step.

Recursion and Backtracking

Recursion solves a problem by solving a smaller copy of itself. Backtracking adds the idea of trying a choice, exploring, and undoing the choice. Subsets, permutations and puzzles all follow this pattern.

Start from zero

The two parts of recursion

Every recursive function needs a base case that stops the recursion and a recursive case that calls itself with a smaller input. Factorial: n! = n × (n − 1)!, with base case 0! = 1.

The call stack

Each call waits for the one it started. Very deep recursion (more than about 1000 levels in Python) can crash; raise the limit with sys.setrecursionlimit or convert to a loop.
A recursion tree for subsets

Memoisation

Plain Fibonacci repeats the same subproblems and takes exponential time. Store results in a dictionary or use functools.lru_cache so each subproblem is solved once. This is the bridge to dynamic programming.

Generating subsets and permutations

Subsets: for each element decide include or skip, giving 2ⁿ results. Permutations: choose an unused element, recurse, then unchoose it (backtrack). Python has itertools, but understanding the recursion matters for puzzles.

N-Queens and constraint puzzles

Place one queen per row. For each column, check that no earlier queen attacks it (same column or diagonal). If the placement works, recurse to the next row; if it fails, try the next column. Backtracking prunes impossible branches early.

Other classics

Tower of Hanoi needs 2ⁿ − 1 moves. Combination sum picks numbers to reach a target, allowing repeats. Maze problems explore four directions and mark cells visited.

Formula and rule box

  • Base case first, then a smaller recursive call
  • Fibonacci with memo: O(n)
  • Subsets: 2ⁿ; permutations: n!
  • Tower of Hanoi moves: 2ⁿ − 1
  • Backtracking: choose → explore → unchoose
  • N-Queens (n = 4): 2 solutions; (n = 8): 92

Step-by-step method

  1. Define the smaller subproblem.
  2. Write the base case.
  3. Make the recursive call and combine the answer.
  4. For backtracking, undo the change after returning.

Stack and Queue

A stack is last-in, first-out and a queue is first-in, first-out. They model undo operations, nested brackets, expression evaluation and level-by-level exploration.

Start from zero

Stack

Operations: push (add on top), pop (remove top), peek (look at top). In Python use a list with append and pop. Typical uses: balanced brackets, reversing, undo, evaluating postfix expressions, next-greater-element.

Queue and deque

Operations: enqueue at the back, dequeue from the front. In Python use collections.deque (popleft is O(1), unlike list.pop(0)). Typical uses: BFS, scheduling, sliding-window maximum with a deque.
A stack checking brackets

Balanced brackets

Scan the string. Push every opening bracket. For each closing bracket, the stack must not be empty and its top must be the matching opener; pop it. The string is balanced if the stack is empty at the end.

Next greater element

Process from left to right with a stack of indices whose answer is not found. When a bigger element arrives, pop smaller ones and set their answer. Each index is pushed and popped once: O(n).

Postfix evaluation

Read tokens: push numbers; for an operator pop two numbers, apply the operator (second popped is the left operand) and push the result. The final stack top is the answer.

Monotonic stack idea

Keep the stack in increasing or decreasing order. Used for nearest smaller or greater values, daily temperatures and histogram areas.

Formula and rule box

  • Stack: LIFO; queue: FIFO
  • Python stack: list.append / list.pop
  • Python queue: collections.deque, popleft()
  • Balanced brackets ⇔ stack empty at the end
  • Next greater element: O(n) with a monotonic stack
  • Postfix: operand order matters for − and ÷

Step-by-step method

  1. Decide: do you need LIFO or FIFO?
  2. Define what you push and when you pop.
  3. Handle the empty stack carefully.
  4. Check the final state of the stack.

Matrix and 2D Arrays

A matrix is an array of arrays. Matrix problems are mostly about traversal order: rows, columns, diagonals, spirals and rotations. Careful index handling is the whole skill.

Start from zero

Reading a matrix

First line: rows r and columns c. Then r lines of c numbers. Python: g = [list(map(int, input().split())) for _ in range(r)]. C++: a 2D vector or array.

Traversals

Row-wise: two nested loops. Column-wise: swap the loops. Main diagonal: cells where i == j. Anti-diagonal: i + j == n − 1. Boundary: cells in the first or last row or column.
Spiral order, transpose and diagonals

Transpose and rotation

Transpose swaps A[i][j] with A[j][i]. To rotate 90° clockwise, transpose and then reverse each row. To rotate anticlockwise, transpose and then reverse the order of rows.

Spiral order

Keep four boundaries: top, bottom, left, right. Print the top row, then the right column, then the bottom row (reversed), then the left column (reversed), shrinking the boundaries after each side. Stop when they cross.

Row and column sums, searching

Compute sums with one pass. In a matrix sorted by rows and columns, start from the top-right corner: move left if the value is too large, down if too small. O(r + c).

Grid neighbours

Use direction arrays: dirs = [(1,0),(-1,0),(0,1),(0,-1)] and check bounds before accessing a neighbour. This is the base of flood fill and path problems.

Formula and rule box

  • Main diagonal: i == j; anti-diagonal: i + j == n − 1
  • Rotate 90° clockwise = transpose + reverse each row
  • Four neighbours: (±1, 0), (0, ±1)
  • Spiral: top → right → bottom → left, shrink boundaries
  • Sorted matrix search: start at the top-right corner

Step-by-step method

  1. Draw a small matrix and mark the index pattern.
  2. Write the loop limits for each side or direction.
  3. Check bounds before using neighbours.
  4. Test with 1 × 1, 1 × n and n × 1 matrices.

Greedy Algorithms

A greedy algorithm makes the locally best choice at each step and never looks back. It is fast and simple, but it works only when the problem has a special structure, so you must understand why it is correct.

Start from zero

The greedy idea

At each step take the choice that looks best right now (earliest finish, largest coin, highest ratio). If the problem has the greedy-choice property, these local choices add up to a global optimum.

Activity selection

Given intervals, pick the maximum number that do not overlap. Sort by end time; take an interval if its start is at least the end of the last chosen one. This is provably optimal.
Pick the activity that ends first

Coins and change

With coin systems like 1, 5, 10, 25, taking the largest coin first gives the minimum coins. For arbitrary coins (for example 1, 3, 4), greedy can fail: 6 = 4 + 1 + 1 (3 coins) but 3 + 3 uses 2 coins, so use dynamic programming.

Fractional knapsack

Sort items by value per weight and take as much as possible of the best items. Greedy is optimal when items can be split (unlike 0/1 knapsack).

Sorting-based greedy

Many greedy problems start with a sort: minimum platforms (sort arrivals and departures), meeting rooms, assigning cookies to children, job scheduling with deadlines, jump game (track the farthest reachable index).

How to check a greedy idea

Try to find a counterexample with small numbers. If you cannot break it and an exchange argument works (swapping a non-greedy choice for the greedy one never hurts), the greedy is probably right.

Formula and rule box

  • Activity selection: sort by end time
  • Fractional knapsack: sort by value/weight
  • Greedy coin change works only for canonical systems
  • Jump game: reach = max(reach, i + a[i])
  • Minimum platforms: sort arrivals and departures

Step-by-step method

  1. Decide what 'best choice' means.
  2. Sort by the right key.
  3. Take choices in order while they remain feasible.
  4. Try a small counterexample to test the idea.

Dynamic Programming

Dynamic programming (DP) solves a problem by building the answer from answers to smaller overlapping subproblems and remembering them. DP is the usual tool for the Medium coding problem, so it is worth learning well.

Start from zero

When to use DP

Use DP when (1) the problem breaks into smaller versions of itself and (2) the same subproblems repeat. Typical phrases: minimum or maximum, number of ways, can we make, longest. If a greedy idea fails and brute force is exponential, try DP.

The five steps

1. Define the state (what dp[i] or dp[i][j] means). 2. Write the transition (how it depends on smaller states). 3. Set the base cases. 4. Choose the order (usually small to large). 5. Read the answer from the right cell.
A DP table for minimum coins

1D examples

Climbing stairs: dp[i] = dp[i−1] + dp[i−2]. House robber: dp[i] = max(dp[i−1], dp[i−2] + a[i]). Minimum coins: dp[a] = 1 + min(dp[a − c]) over coins c ≤ a, with dp[0] = 0.

2D examples

Longest common subsequence: if the characters match, dp[i][j] = dp[i−1][j−1] + 1; otherwise max(dp[i−1][j], dp[i][j−1]). Grid paths: dp[i][j] = dp[i−1][j] + dp[i][j−1]. 0/1 knapsack: dp[w] = max(dp[w], dp[w − wt] + value), looping w from high to low.

Longest increasing subsequence

dp[i] = 1 + max(dp[j]) for j < i with a[j] < a[i]. This is O(n²); the answer is the maximum dp[i]. A faster O(n log n) method exists with binary search.

Memoisation versus table

Top-down (recursion with memo) is easier to write; bottom-up (loops) is faster and avoids recursion limits. Both give the same answer.

Formula and rule box

  • Climbing stairs: dp[n] = dp[n−1] + dp[n−2]
  • Coin change: dp[a] = 1 + min(dp[a − c])
  • LCS: match → dp[i−1][j−1] + 1, else max of neighbours
  • 0/1 knapsack: dp[w] = max(dp[w], dp[w − wt] + val)
  • LIS: dp[i] = 1 + max dp[j] with a[j] < a[i]
  • Grid paths: dp[i][j] = dp[i−1][j] + dp[i][j−1]

Step-by-step method

  1. Define the state in one sentence.
  2. Write the transition and base cases.
  3. Fill the table in the right order.
  4. Print the cell that holds the answer.

Linked Lists, Trees and Graphs

These structures appear less often in the Easy and Medium problems but are worth knowing at a basic level: reversing a list, tree traversals, and breadth-first or depth-first search on graphs and grids.

Start from zero

Linked list

A chain of nodes, each holding a value and a pointer to the next node. Typical tasks: reverse the list (keep previous, current, next), find the middle (slow and fast pointers), detect a cycle (slow and fast meet), merge two sorted lists.

Binary tree

Each node has at most two children. Depth-first traversals: preorder (root, left, right), inorder (left, root, right) and postorder (left, right, root). Height = 1 + max(height of left, height of right). Level-order traversal uses a queue.
BFS levels on a small graph

Binary search tree (BST)

Left values are smaller and right values are larger. Inorder traversal gives sorted order. Search, insert and delete take O(h) where h is the height.

Graphs

Store a graph as an adjacency list: a dictionary from each node to its neighbours. BFS uses a queue and finds the shortest path (fewest edges) in an unweighted graph. DFS uses recursion or a stack and finds connected components, cycles and reachability.

Grids as graphs

A grid cell connects to its four neighbours. Counting islands, flood fill and shortest path in a maze are BFS or DFS on the grid. Keep a visited array so each cell is processed once.

Common patterns

Number of connected components: start a DFS from every unvisited node and count the starts. Shortest path in a grid: BFS from the start storing distance. Detect a cycle in an undirected graph: DFS and see a visited neighbour that is not the parent.

Formula and rule box

  • Preorder: root, left, right
  • Inorder: left, root, right (sorted for a BST)
  • Postorder: left, right, root
  • Height = 1 + max(h(left), h(right))
  • BFS: queue, shortest path in an unweighted graph
  • DFS: recursion or stack, components and cycles
  • Edges in a tree with n nodes: n − 1

Step-by-step method

  1. Choose the structure: list, tree or graph.
  2. Pick BFS (shortest path) or DFS (explore everything).
  3. Keep a visited set.
  4. Handle disconnected graphs by starting from every node.

Bit Manipulation

Numbers are stored as bits. Bit tricks give very fast solutions to counting, parity and 'find the unique element' problems, and are the key to subset enumeration for small n.

Start from zero

Binary basics

Decimal 13 is 1101 in binary (8 + 4 + 1). Each bit is a power of two. Python: bin(13) returns '0b1101'; C++ can print with bitset.

The operators

AND (&): 1 only if both bits are 1. OR (|): 1 if either is 1. XOR (^): 1 if the bits differ. NOT (~) flips bits. Left shift x << k multiplies by 2ᵏ; right shift x >> k divides by 2ᵏ (floor).
Bit operations on 13 and 6

Useful tricks

Check the k-th bit: (x >> k) & 1. Set a bit: x | (1 << k). Clear: x & ~(1 << k). Toggle: x ^ (1 << k). Odd or even: x & 1. Power of two: x > 0 and (x & (x − 1)) == 0.

Counting set bits

Brian Kernighan's trick: x &= x − 1 removes the lowest set bit, so loop until x is 0 and count the steps. Python: bin(x).count('1') or x.bit_count().

XOR properties

a ^ a = 0, a ^ 0 = a, and XOR is commutative. So XOR-ing all numbers of an array where every number appears twice except one leaves the unique number. Swap two numbers without a temporary: a ^= b; b ^= a; a ^= b.

Subsets with bitmasks

For n ≤ 20, every number from 0 to 2ⁿ − 1 represents a subset: bit i tells whether element i is included. Loop over masks and test each bit.

Formula and rule box

  • x & 1 → odd or even
  • x & (x − 1) removes the lowest set bit
  • Power of two: x & (x − 1) == 0 (x > 0)
  • a ^ a = 0, a ^ 0 = a
  • x << k = x × 2ᵏ; x >> k = x // 2ᵏ
  • Subsets of n items: masks 0 … 2ⁿ − 1

Step-by-step method

  1. Write the numbers in binary on paper.
  2. Pick the operator that creates the pattern you need.
  3. Test small values (0, 1, powers of two).
  4. Remember Python's integers are unbounded; mask if needed.

Technique wins marks in the coding round as much as knowledge. A calm plan for the 90 minutes, a habit of testing edge cases and a clean way to debug will save you from the most common failures.

Spend 5 minutes reading both problems. Solve the Easy problem first (about 30–35 minutes): it usually has a direct approach. Then take the Medium problem (about 50 minutes). Keep the last 5 minutes for testing. Always submit something that passes the sample tests before polishing.

Brute force first

Write the simplest correct solution first, even if it is slow. It scores partial marks on small hidden tests. Then look for the repeated work and optimise (prefix sums, hash map, sorting, DP). A slow correct answer beats a fast wrong one.

1. Programming Fundamentals and Input/Output

  • int ≈ ±2.1 × 10⁹; long long ≈ ±9.2 × 10¹⁸
  • Use long long when a product can exceed 2 × 10⁹
  • (a × b) mod m = ((a mod m) × (b mod m)) mod m
  • Multiple tests: read T, then loop T times
  • Digit sum: repeat n % 10 and n // 10
  • Leap year: divisible by 4 and (not by 100 or divisible by 400)

2. Time Complexity and Constraints

  • ≈10⁸ operations/second (C++), ≈10⁷ (Python)
  • n ≤ 10⁵ → O(n log n) or better
  • n ≤ 5,000 → O(n²) is fine
  • n ≤ 20 → O(2ⁿ) is fine
  • sort = O(n log n); binary search = O(log n)
  • dict/set lookup = O(1) average

3. Arrays

  • P[i] = a[0] + … + a[i−1]; sum(l..r) = P[r+1] − P[l]
  • Kadane: cur = max(x, cur + x); best = max(best, cur)
  • Missing number from 1..n: n(n+1)/2 − sum
  • Rotate left by k: a[k:] + a[:k] (k %= n)
  • Sum of first n numbers: n(n+1)/2

4. Strings

  • s[::-1] reverses a string
  • Anagram ⇔ equal character counts
  • Number of substrings = n(n + 1)/2
  • ord('a') = 97; ord(c) − 97 gives 0–25
  • Palindrome: s == s[::-1]
  • Join pieces: ''.join(list)

5. Math and Number Theory

  • Prime test: check divisors up to √n
  • gcd(a, b) = gcd(b, a mod b)
  • lcm(a, b) = a × b / gcd(a, b)
  • pow(a, b, m) computes a^b mod m
  • Divisors of p^a q^b: (a + 1)(b + 1)
  • Trailing zeros of n! = n//5 + n//25 + n//125 + …
  • Sum 1..n = n(n + 1)/2

6. Sorting and Searching

  • Sorting: O(n log n)
  • Binary search: O(log n)
  • mid = lo + (hi − lo) // 2
  • count(x) = bisect_right − bisect_left
  • Sort key: (−marks, name) for marks descending
  • Searching on the answer: check(mid) is monotone

7. Hashing, Sets and Maps

  • Membership in set/dict: O(1) average
  • Frequency: d[x] = d.get(x, 0) + 1
  • Two-sum: look for target − x in seen
  • Subarray sum K: count[prefix − K]
  • Group key for anagrams: sorted(word)
  • Counter(a).most_common(1) gives the most frequent item

8. Two Pointers and Sliding Window

  • Pair sum on sorted array: i from the left, j from the right
  • Window sum: new = old + a[right] − a[left]
  • Longest unique substring: move left past the last duplicate
  • Time: O(n) because each pointer moves at most n times
  • Smallest subarray with sum ≥ S: shrink while sum ≥ S

9. Recursion and Backtracking

  • Base case first, then a smaller recursive call
  • Fibonacci with memo: O(n)
  • Subsets: 2ⁿ; permutations: n!
  • Tower of Hanoi moves: 2ⁿ − 1
  • Backtracking: choose → explore → unchoose
  • N-Queens (n = 4): 2 solutions; (n = 8): 92

10. Stack and Queue

  • Stack: LIFO; queue: FIFO
  • Python stack: list.append / list.pop
  • Python queue: collections.deque, popleft()
  • Balanced brackets ⇔ stack empty at the end
  • Next greater element: O(n) with a monotonic stack
  • Postfix: operand order matters for − and ÷

11. Matrix and 2D Arrays

  • Main diagonal: i == j; anti-diagonal: i + j == n − 1
  • Rotate 90° clockwise = transpose + reverse each row
  • Four neighbours: (±1, 0), (0, ±1)
  • Spiral: top → right → bottom → left, shrink boundaries
  • Sorted matrix search: start at the top-right corner

12. Greedy Algorithms

  • Activity selection: sort by end time
  • Fractional knapsack: sort by value/weight
  • Greedy coin change works only for canonical systems
  • Jump game: reach = max(reach, i + a[i])
  • Minimum platforms: sort arrivals and departures

13. Dynamic Programming

  • Climbing stairs: dp[n] = dp[n−1] + dp[n−2]
  • Coin change: dp[a] = 1 + min(dp[a − c])
  • LCS: match → dp[i−1][j−1] + 1, else max of neighbours
  • 0/1 knapsack: dp[w] = max(dp[w], dp[w − wt] + val)
  • LIS: dp[i] = 1 + max dp[j] with a[j] < a[i]
  • Grid paths: dp[i][j] = dp[i−1][j] + dp[i][j−1]

14. Linked Lists, Trees and Graphs

  • Preorder: root, left, right
  • Inorder: left, root, right (sorted for a BST)
  • Postorder: left, right, root
  • Height = 1 + max(h(left), h(right))
  • BFS: queue, shortest path in an unweighted graph
  • DFS: recursion or stack, components and cycles
  • Edges in a tree with n nodes: n − 1
