Before you start

How a round works

  • Every question gets a fresh 20:00 timer each time you open it — there is no shared timer across questions. At 0:00 your code is submitted automatically.
  • The main() driver is fixed — only edit the function(s) shown in the editor.
  • Save & Test runs the sample test cases. Submit also runs the hidden test cases and shows your score.
  • After submitting, review every bug with an explanation and a line-by-line diff of the solution.

Where bugs usually hide

  • Loop bounds: < vs <=, n vs n-1, index i vs i-1.
  • Initialisation: base cases, 0 vs INT_MIN, "infinity" too small.
  • Python traps: ^ is XOR (not power), [[0]*m]*n shares one row, range(n) stops at n-1.
  • Flipped comparisons (min vs max), wrong variable after copy-paste.
  • Overflow: 32-bit int where the answer needs 64 bits.
  • Returning the wrong thing (node vs root, local vs global answer).

How this practice judge works

  • Your browser cannot compile C/C++/Java, so the judge recognises each fix in your code and runs a model of your program, checked against real gcc / g++ / javac / python3 output.
  • So Your Output shows what your program would actually print — including garbage values, crashes and overflows.
  • Make minimal, line-level edits, as in the real test. If a correct fix isn't recognised, compare with the solution diff.

Your code, timers and scores are saved in this browser only.
